# 《姑苏九园》场景碰撞与遮挡标准

本标准适用于府学、苏城、园林和近景谜题层。目标是让美术换版、场景扩充和人物增加时，不再依靠逐处猜测 Y 值修补问题。

## 1. 唯一坐标语义

- 所有几何数据使用背景资产缩放后的世界像素坐标；相机坐标只允许出现在渲染阶段。
- 人物的 `x/y` 永远表示双脚中心点。精灵左上角、身体中心或图片底边不得作为逻辑坐标。
- 人物精灵尺寸和碰撞尺寸互相独立。碰撞只取脚底附近的小矩形，使人物身体可以自然地与树冠、家具和屋檐重叠。
- 角色图集必须记录每帧的真实不透明轮廓与鞋底 Y，不可仅按整张图均分格子；绘制时用鞋底对齐逻辑脚点。若底图有近大远小透视，只改变精灵显示身高和接地阴影，不移动脚点或偷偷改变碰撞数据。
- 背景、美术裁片、碰撞、遮挡、交互点必须使用同一资产版本和同一世界尺寸。

### 人物与底图比例闸门

1. 图集逐帧记录实际不透明裁片和鞋底坐标；禁止用 `frame * 362` 等整格透明边裁图，再拿“绘制矩形高度”冒充可见人物身高。`src/render/scholar-sprite.ts` 现分别保存白衣书生与沈砚秋两套实测裁片。
2. 每张底图单独记录视觉标尺：选一个与人物同景深的门、窗或墙面，量其**图面像素**高度，写出人物在出生脚点、最远和最近脚点的可见身高。没有测绘尺寸时，只能叫“视觉标定”，不能写成真实建筑与人体的米制比例。
3. 近大远小只由脚点 Y 映射到精灵显示身高；用裁片真实鞋底对齐同一逻辑脚点，阴影跟随脚点，碰撞盒和交互半径不随画面缩放。
4. 把选定场景的出生点比例带、远近端点和鞋底对齐写成自动测试；换底图、改镜头或换精灵时先改标尺再验收。调试层显示人物可见像素高与参照物像素高，人工仍须在窗前、左右墙边和前景各试走一次。

编辑器的“人物比例 / 脚点”层用于人工标定：拖动真实精灵脚点到同景深的门前、门后与近景，调 40%～250% 的**可见身高倍率**，再保存草稿并从右上角打开草稿预览。倍率是每张底图独立的视觉参数；旧草稿缺字段按 100% 读取。它既不缩放背景，也不改变脚点、碰撞盒、交互距离和远近透视曲线。当前留园接入草稿预览的场景会读取倍率；未接入试玩页的底图只在编辑器内显示，不能据此宣称运行态通过。正式定稿仍须记录参照物和前、中、后景三点的人物像素高。

沧浪亭复廊是受约束运动的例外，但仍使用同一个编辑器：选择“沧浪亭 · 复廊近景”，在精细轮廓层逐个选择 `corridor-post-01` 至 `08`，拖动青色遮挡裁片和黄色落地线；人物比例层可调可见身高。保存草稿后点“预览复廊人物比例与廊柱遮挡”。`corridor.html?actorDraft=1` 只读取人物倍率和视觉遮挡；预览脚点、Tile、碰撞与三窗受约束路线都不导入。普通 `corridor.html` 不加载草稿。默认身高 52px，8 根柱子的初始细矩形仅是旧画面裁片的编辑起点，均非实测；必须由玩家对着底图逐柱校准。旧草稿会增量补缺失廊柱，不覆盖同名已编辑物件。曾经用一条代码绘制的通长前栏压在人物前面；v4 底图改为素墙石基后，这条合成前栏已删除，接地改靠精灵真实脚点和局部阴影，不以删除此栏反证实景无栏。

三窗研究房间当前以 `src/data/liuyuan-window-room-study.ts` 的 416～528 脚点范围映射 145～175px 人物可见身高，出生点约 164px；中央窗图面开口约 176px。此比值来自游戏画面标定，不是“洞天一碧”的实测尺度。留园入口、小庭、绿荫轩、花木作业院、石林、观云峰旧切片和东厅已改用实际裁片与鞋底锚点；入口仍用 v2 白模的近处约 55px、远处约 44px，其他六张旧切片暂保留原画面约 84px 可见高度。入口 v3/v4 俯视候选的 62～75px 人物定标随画面一起撤回；换成与府学、小庭一致的斜俯视近景后，必须再以门、台阶和角色三点重标并在真实浏览器实走。

## 2. 一个物件，一份几何数据

每个场景物件用稳定 `id` 声明以下数据：

```ts
interface SceneGeometryObject {
  id: string;
  colliders?: CollisionRect[];
  occluder?: {
    id: string;
    depthY: number;
    polygons: WorldPoint[][];
  };
}
```

- `colliders`：决定人物能否走入，只覆盖墙基、树干、花台和家具落地范围。规则物件可用矩形，不规则物件用凸多边形；凹形轮廓拆成多个凸多边形。
- 一个连续石栏或池岸即使看似一件物件，只要轮廓有内凹，就要在该物件下拆成数块凸碰撞体；不能把编辑器里的单个凹多边形直接交给 SAT。场景回归检查应抽检凸性及玩家能否沿岸通过。
- `occluder.polygons`：决定物件哪些像素可以盖住人物，必须贴合树冠、屋檐、门柱等真实轮廓。
- `depthY`：物件与地面接触的落地线。人物脚点与它共同进入深度排序。
- 有屋顶跨越通路时，落地线应取支撑它的柱脚／墙脚，不取檐口的屏幕 Y；人物脚点未越过柱脚之前，屋顶裁片应继续盖住人物上半身。调试层同时画出青色遮挡轮廓、黄色落地线和白色脚点。
- `effects`：水纹、雾、落叶等动态区域；使用世界坐标多边形，并用 `holes` 扣除桥体、岸石和建筑。
- 交互区域、出口和目标出生点属于玩法数据，可以引用同一物件 `id`，不得反过来充当碰撞盒。

碰撞体与遮挡体通常不同。树冠可以遮住人物，但不能作为整块碰撞；门楼可以遮住人物，但门洞必须仍可通行。

动态效果也不能用场景包围盒。水纹算法只负责在蒙版中生成波段，不得知道某座桥或某个池塘的坐标；池岸轮廓和桥体扣除区由场景数据提供。相机移动时以世界坐标生成效果，再转换到屏幕坐标，避免波纹随镜头漂移。

复廊角色倒影复用同一水域多边形和岸石扣除区；岸线按 `CORRIDOR_WATER_EDGE` 插值，倒影从水内缘向下绘制，低透明度、竖向压缩，并叠在水纹下。它是画面效果，不能参与碰撞或人物深度排序。修改底图、池岸或镜头后须同时重标水纹蒙版与岸线；静态测试只验证坐标锚点，透明度、倒影是否压在岸石上仍须看实际画面。

## 3. 地形与精确物件的职责

- Tile 网格只负责大片地形：水面、建筑主体、院墙、道路和室内区域。
- 独立物件使用连续世界坐标：树、花台、床、箱笼、书案、门柱和桥栏。
- 不足一个人物脚底宽度的缝隙应封闭，不能形成视觉上不存在的路线。
- 门、台阶和桥是 Portal/通路，不用“暂时关闭碰撞再打开”的特殊逻辑穿越。

新全园场景先在编辑器的“通路骨架 / 门洞”层标入口、门洞、桥头、厅堂和剧情抵达点，再铺 Tile。骨架的节点、连线、候选/已核/禁行状态会保存进同一份场景 JSON；禁行边不参与入口连通性。它只证明路线关系，不证明线段在像素图上不会穿墙、落水或穿过未开的门。只有候选线逐条核图、实走并标为已核后，才允许转为玩家移动几何。

路线节点另存 `level`（0=地面，1+ 为楼廊或山径上层）；跨层连线必须设为“楼梯 / 上山径”，普通平层步行线不可直接连接上下层。桥面用独立连接方式标记，后续标定桥面 Tile 和桥栏遮挡。`level` 是游戏空间层，不是屏幕 Y 坐标或遮挡落地线；退思园天桥、环秀山庄山径不能靠改一个 Y 值解决。

## 4. 深度排序

所有动态人物与静态前景进入同一个稳定排序队列：

1. 人物使用脚点 `y`。
2. 场景物件使用 `depthY`。
3. 从小到大绘制；相同深度使用固定 `order` 保证结果不闪动。
4. 禁止根据玩家位置整体开关一张巨大前景图；树冠、屋檐、门柱必须拆成贴合轮廓的多边形。

## 5. 新场景制作流程

1. 锁定背景资产版本、原始尺寸和游戏世界尺寸。
2. 标记可行走地形、不可行走大轮廓和所有真实门洞。
3. 为独立物件绘制落地碰撞体。
4. 为会遮住人物的区域绘制遮挡多边形。
5. 在物件接地点设置 `depthY`。
6. 设置交互点、触发半径、Portal 和抵达后的脚点。
7. 打开几何调试层，逐一核对美术轮廓。
8. 运行关键路线测试，再进行键盘和触屏实走。

换背景资产后必须从第 1 步重新校准，禁止保留旧图坐标后凭感觉补偏移。

## 6. 调试颜色与入口

府学样板使用：`home.html?debug=geometry`

- 红色半透明：实体碰撞体
- 青色轮廓：遮挡多边形
- 黄色横线：物件落地深度线
- 蓝色区域：水面等动态效果蒙版
- 橙色轮廓：从特效蒙版扣除的桥体或前景
- 洋红色矩形：人物脚底碰撞盒
- 白色十字：人物真实世界坐标

可与定位参数组合，例如：

- `home.html?debug=geometry&at=tree-front`
- `home.html?debug=geometry&at=gate-under`
- `home.html?debug=geometry&at=room-step`

整园场景还显示语义锚点：绿色为已核实景关系，黄绿色为待复核推演，紫色为玩法艺术加工。语义锚点用于核对建筑关系和可达脚点，不得充当碰撞盒。

## 7. 完成验收

- 角色不能穿过墙基、树干、花台和家具，也不能被空气墙挡在可见道路上。
- 人物从物件北侧到南侧经过时，遮挡关系只在落地线附近切换且不抖动。
- 所有可见门洞、桥面与台阶均可抵达；所有非入口切面均不可穿入。
- 相机移动时背景与前景裁片没有 1px 漂移。
- 入口到斋舍、床铺、书案、明伦堂和出口的路线测试全部通过。
- 几何校验无越界、负尺寸、少于三点的多边形或错误 ID。

自动验收脚本为 `scripts/verify-fuxue-geometry.ts`。它会检查边界停步值以及从出生点到所有交互锚点的连通性；新增或移动物件后必须运行。

全场景验收脚本为 `scripts/verify-all-scenes.ts`，覆盖府学、沧浪亭白模、复廊结构试铺、整园导航和复廊英雄场景。

府学的标准实现位于 `src/data/fuxue-geometry.ts`；其他场景复制数据结构，不复制府学坐标。
