# 场景编辑器 · 协作交接

入口：[场景几何编辑器](geometry-editor.html)。**序章府学 Home 的编辑方法是统一标准**：各场景使用同一个世界像素坐标、Tile/独立物件/遮挡落地线/动态效果/剧本锚点/通路骨架文档结构、同一套保存与导出按钮，而不是另做一个只放图片的目录。左栏「场景底图」现按园林分组，收录 22 张正在制作或保留对照的场景底图；已否决的花房墙脚玉兰 v2、冠云峰通用庭院 v0 不在清单。切换场景会先保存当前浏览器草稿，各场景使用独立 ID，互不覆盖。

编辑器左侧「府学标准 · 本幕分层」逐幕显示年代证据、底图、Tile、碰撞、前景遮挡、水纹、剧本点、门路以及草稿实走是否已有数据。**出现数量只表示具备可校准的数据，不表示历史真实性或实走验收通过。**

下方「本幕考据卡」把已知空间关系、游戏演绎、制作红线和来源分开显示。所有 22 张底图都须有这张卡；旧沧浪亭试稿与网师园也已补齐。研究底图仍是研究底图，不能因几何点数增加而自动升为可玩关卡。复廊近景属于受约束运动，不能用普通自由行走 Tile 的缺项去误判；其路线改动须导出后单独接入。

冠云峰 v2 另有「本地 RAG 候选」制作面板，列出书中待核的窗式、东园扩建年代和院落层次线索。只提供原书定位，不把 OCR 文句或原图打包进游戏；版权、页码、部位和故事时段都未审核。考据卡中仍写“1890”的地方标为**旧稿口径待时间审计**，不再当作当前时间定案。[时间设定与史实边界](../姑苏九园-时间设定与史实边界.md)已补 CH3／CH7／CH8 跨章时间冲突：冠云峰 v2 可继续做几何校准，但南厅、北楼、浣云沼不能仅凭现状资料升为同年完成的正式美术。

## 你可以先编辑什么

1. **留园章**：入口白模、古木交柯小庭、绿荫轩、花木作业院、石林小院、冠云峰南厅 v2，以及独立的厅前玉兰植栽语法候选，都能从下拉菜单进入。前六幕和厅前候选各有「预览当前草稿」；入口预览现在使用与编辑器相同的无标注底图，并读取你编辑的 Tile 与碰撞。
2. **沧浪亭复廊近景**：已加入同一编辑器。`corridor-post-01` 至 `08` 是独立廊柱物件，可拖青色遮挡轮廓、调黄色落地线；保存后右上角可预览人物比例和遮挡。水纹内缘、三个取景脚点及廊线仍可在编辑器标定，但受约束路线、Tile、碰撞和三窗机制**不会自动读取草稿**，须导出 JSON 后审核接入。柱形初值只是待精修裁片，不是实测复原。
3. **其他整园试稿**：沧浪亭、网师园、留园整园、退思园、耦园、拙政园、环秀山庄、艺圃均可标定。它们多是研究候选，不因「能编辑」而成为已考据、可玩的正式场景。

## 一次可靠的交接

选择底图 → 拖拽 Tile / 碰撞 / 遮挡 / 水纹 / 剧本锚点 / 通路 → 点击「确认保存为最新版本」→ 用右上角「预览当前草稿」（若有）实走 → 返回编辑器修订 → 点击「下载 JSON 文件」并把文件交给我审核固化。浏览器草稿只保存在你的浏览器环境；我不能把「已保存」误当成代码源已经更新。

预览页目前读取 **Tile 与物件轮廓**，但路线节点、剧本锚点、对话和存档触发仍以代码为准；这些编辑需要审核后再接入玩法。旧稿与新稿场景 ID 分开，绝不清空你的浏览器草稿。若场景没有「预览当前草稿」链接，说明它目前只能在编辑器内对图和导出 JSON，不能声称已完成键盘/触屏实走。

对留园章建议先帮我核 **冠云峰 v2 的南厅檐口／柱脚、浣云沼内缘与两岸脚点**，再回头核入口白模的窄廊与漏窗实墙。真实建筑门位与最终选定故事时段的园貌仍需来源，不用生成图猜定。
