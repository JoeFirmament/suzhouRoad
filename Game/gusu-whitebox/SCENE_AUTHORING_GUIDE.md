# 《姑苏九园》场景制作执行指南

这份指南用于真正制作和验收场景；概念和数据约束见 `SCENE_GEOMETRY.md`。

**唯一编辑入口**：府学、苏城、整园、局部园景和谜题近景一律登记到 `src/data/scene-plates.ts`，并通过同一 `geometry-editor.html?scene=<scene-id>` 编辑。不得再为某一场景另建只处理遮挡或比例的孤立编辑器。每个场景用独立 ID 保存草稿；场景资产、世界尺寸、人物比例、Tile、物件碰撞、遮挡/落地线、效果区、剧情锚点和通路骨架应归于同一场景文档。能在编辑器标定不等于已接入试玩：逐项标明预览实际读取的图层，未接入的图层须导出审阅后再进运行态。

## 一、开始前准备

为每个新场景建立一份 `src/data/<scene>-geometry.ts`。先写清：

- 背景资产文件、版本号、原始像素尺寸。
- 游戏中的世界宽高和缩放倍率。
- 人物出生脚点、出口脚点和镜头初始位置。
- 场景采用自由 Tile 导航、导航多边形，还是像复廊近景一样的受约束路径。

不要先写特殊判断。所有位置都先落在几何数据里。

## 二、标定顺序

### 1. 锁定世界坐标

加载背景时只允许一次从资产尺寸到世界尺寸的缩放。记录比例：

```text
worldX = assetX × worldWidth / assetWidth
worldY = assetY × worldHeight / assetHeight
```

相机偏移不参与标定。人物、碰撞、遮挡和特效全部使用换算后的世界坐标。

### 2. 标可行走区域

- 大面积道路、水体、墙体用 Tile。
- 曲线岸边或不规则室内使用导航多边形。
- 狭窄走廊可以使用中心路径加横向 `lane` 范围。
- 所有入口至少比人物脚底盒宽 2px；看起来能走但实际不可走的区域必须在美术上给出阻挡理由。

### 3. 标实体碰撞

只框物件与地面接触的部分。树使用树干/花台，建筑使用墙基，家具使用落地轮廓。规则边界用矩形；斜边和树根用凸多边形；凹形必须拆成多个凸块。禁止把树冠、屋顶或人物全身高度纳入碰撞。

### 4. 标遮挡与落地线

为树冠、屋檐、门柱、栏杆绘制贴边多边形。`depthY` 放在物件接地线：人物脚点小于它时先画人物后画物件，越过后反过来。

### 5. 标动态效果区域

水面使用 `SceneEffectRegion`：

```ts
{
  id: 'pond-ripple',
  kind: 'water-ripple',
  polygons: [水面内缘],
  holes: [桥体, 岸石前景],
  ripple: { color, rowSpacing, segmentSpacing, minLength, maxLength, speedMs }
}
```

先标水面内缘，再扣除桥、石、船和前景植物。不要通过反复修改波纹起点来追背景图；换图只改蒙版。

### 6. 标交互锚点

锚点应放在玩家能够接近的物件前缘，不放在碰撞体中心。每个锚点必须通过“出生点可达”自动测试。

## 三、调试方式

统一使用查询参数：

- 府学：`home.html?debug=geometry`
- 整园：`garden.html?debug=geometry`
- 结构试铺：`slice.html?debug=geometry`
- 复廊近景：`corridor.html?debug=geometry`

府学需要逐点校准时，打开 `geometry-editor.html`。编辑器的“精细轮廓”层提供“添加点”和“删除选中点”按钮，也支持拖拽顶点、拖拽边、整体拖动多边形、Shift 点击边插点、右键删点、拖动黄色落地线。一个物件只有一条落地线，其全部遮挡轮廓共享该深度；不同落地点必须“新建空物件”，或用“当前轮廓拆出”分成独立物件。物件栏和几何类型会显示实时轮廓数量，删除轮廓后同步更新。“大片 Tile 网格”层不使用画笔：拖区域内部整体移动，拖四角改变矩形范围，始终吸附 16px Tile。“保存浏览器草稿”用于中途工作；校验无误后点“确认保存为最新版本”，把完整结果写入稳定版本槽并记录时间。保存后点右上角“返回府学 · 预览草稿”，会进入 `home.html?debug=geometry&draft=1`，直接用最新的 Tile、碰撞、遮挡和水面范围运行；`file://` 往返由当前标签页会话通道保持数据。正式入口不会读取草稿。`home.html?debug=geometry` 顶部也会出现“编辑几何轮廓”入口。

颜色含义：红色碰撞、青色遮挡、黄色深度线、洋红色人物脚底盒、白色人物脚点、蓝色特效区域、橙色特效扣除区。整园语义锚点另用绿色（已核）、黄绿色（推演）、紫色（艺术加工）；三者不参与碰撞。

编辑器另外以绿色显示交互锚点。绿色点当前只用于核对交互位置，不会被误写入碰撞轮廓。

调试时依次走四条路线：

1. 沿每堵墙贴边走，检查是否抖动或被空气墙阻挡。
2. 从四个方向接近树与家具，检查停步距离。
3. 穿过所有门、桥和台阶，检查入口宽度和遮挡切换。
4. 从出生点走到每个任务点，再沿出口返回。

## 四、执行自动验收

在 `Game/gusu-whitebox` 目录运行：

```bash
TSC=/Users/quill/.workbuddy/binaries/node/workspace/node_modules/.bin/tsc
ESB=/Users/quill/.workbuddy/binaries/node/workspace/node_modules/.bin/esbuild
NODE=/Users/quill/.workbuddy/binaries/node/versions/22.22.2-3/bin/node

$TSC -p tsconfig.json
$ESB scripts/verify-all-scenes.ts --bundle --platform=node --outfile=/tmp/verify-all-scenes.cjs
$NODE /tmp/verify-all-scenes.cjs
```

自动验收必须满足：

- 数据尺寸、出生点和人物脚底盒有效。
- 所有交互/任务点从出生点可达。
- 受约束路径无重合点，任务顺序沿路径递增。
- 水域蒙版、多边形和扣除区不越界。
- 类型检查和浏览器控制台无错误。

## 五、资产换版

资产一旦换版，不允许只给现有坐标增加统一偏移。按以下顺序处理：

1. 更新资产版本与世界尺寸。
2. 重标入口和接地线。
3. 重标碰撞体。
4. 重标遮挡多边形。
5. 重标水面等效果蒙版与扣除区。
6. 重标交互锚点。
7. 跑全场景自动验收。
8. 打开调试层实走并截图复核。
