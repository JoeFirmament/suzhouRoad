## 3. 技术栈建议（两条路线）

| 路线 | 适合 | 理由 |
|------|------|------|
| **A · 原生 Canvas + TypeScript**（推荐起步） | 团队=现在的我们，白模阶段 | 已有《沧浪亭-大场景游走测试.html》（**已归档 `archive/`**）验证了原生 canvas 跑得动核心循环；无框架黑盒，渲染层逻辑层已分离（换资产只换渲染）；包体最小 |
| **B · Phaser 3**（白模验证后可迁移） | 需要场景管理/补间/物理/音频总线规模化时 | 九园并行开发、动画量大、需要编辑器管线时再上；Phaser 生态的 Tiled 支持成熟 |

**资产管线（两路线通用）**：
- 地图：**Tiled** 编辑器 → 导出 JSON → 运行时渲染（刘敦桢实测图 → 白模 tilemap → Tiled 正式图，一条线走完）
- 像素资产：Aseprite 定稿 → 图集打包（FreeTexPacker）→ PNG/WebP
- 色板锁定：定稿四版概念图的色板收进 .hex 文件，全管线共用（防资产色漂）

**部署**：nginx + `gzip_static` 预压缩 + 内联关键 JS——沿用康复站已验证的链路；九园按需加载（JSON 地图 + 图集分包），首包只装沧浪亭。

## 4. Web 特有设计约束（写进 GDD 的四条）

1. **存档双保险**：localStorage 自动存 + "房契"导出码（一串字符粘贴恢复）——浏览器清缓存是 Web 游戏第一杀手，房契叙事与住店存档天然同构。
2. **首包预算 [PLACEHOLDER]**：目标首开 ≤ 10MB（沧浪亭一园：地图 JSON + 图集 + 信件文案），加载页用"买园票"排队的主题化表现。
3. **分享钩子落地**：URL直达 + 相册图片右键即存——"考你漏窗截图认园林"的社交循环在 Web 上零摩擦。
4. **微信内置浏览器兼容**：国内传播主入口大概率是微信打开——iOS WKWebView 的音频手势限制、触屏摇杆（原型已验证）、屏宽适配三项进验收清单。

## 5. 风险两张牌

| 风险 | 对策 |
|------|------|
| Web 长会话留存弱于原生（60–90min 单局是逆水行舟） | 庭院分段即存即走；每段 10–15min 自成闭环，"一天"由段拼装——Web 的碎片化反而是分段存档设计的放大器 |
| 像素资产产量是长期瓶颈 | 白模期继续零资产程序化渲染（原型已验证）；资产生产等纸面测试 + 刘敦桢总平面图裁决后批量启动，避免测完重画 |
