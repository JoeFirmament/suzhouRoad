## 0. 本文件管什么 / 不管什么

**管**：剧本文件的组织方式、字段定义、命名规则、台词排版、参数与占位写法、考据标注、验收清单。

**不管**：玩法规则（归任务设计系统定案）、视觉规格（归统一像素视觉系统定案）、工程实现（归白模工程与场景几何标准）。

一条铁律：**剧本里出现的每个数值，都必须能追到 `gusu-whitebox/src/config.ts` 的一个键名，或标 `[PLACEHOLDER]`。禁止在剧本里写孤立的魔法数字。**

## 1. 三层文件分工

剧本不是一份文件，是三层。每层的读者和粒度不同，不要混写。

| 层 | 文件 | 粒度 | 读者 | 作用 |
|---|---|---|---|---|
| 总谱 | `姑苏九园-剧本总谱.md` ⚠️ **尚未建立（待建）** | 一章一行 | 自己（做全局判断） | 九章的命题、人物弧、招牌时刻、六艺进境点、解锁顺序。**建表前暂由《任务设计系统定案》§12「九园首批任务种子」代职** |
| 分场脚本 | `姑苏九园-剧本-序章.md`<br>`姑苏九园-剧本-CH1沧浪亭.md` | 一场一卡 | 自己（写作/美术/程序同一人） | 可直接照着做的最小单元 |
| 台词表 | 附在分场脚本内 | 一行一句 | 文案 / 本地化 / 配音 | 台词与观察文字的逐行文本 |
| **玩法卡** | `姑苏九园-玩法-<编号><名>.md`，如 `姑苏九园-玩法-M1灯谜条.md` | **一款一卡** | 自己（做玩法判定与美术） | 戏中戏 A 轨小游戏与 B 轨章内机制的完整规格，见 **§2.5** |
| **今按** | 附在分场脚本内（**章末或页脚**） | **一章 ≤2 条** | 自己（做考据落点与呈现） | 后世之评。**近现代学人文字的唯一合法容器**，见 **§2.6** |

**场（scene）是剧本最小单元。** 场的定义：**一个可以被独立实现、独立跳过、独立回看的段落**。一场必须能回答"如果玩家只玩这一场，他看到了什么"。

- 一场时长 30 秒–5 分钟。
- 一个"庭院段"= 3 场左右；一章 = 6–10 场。
- 一场超过 5 分钟，说明它其实是两场。

文件命名：`姑苏九园-剧本-<层><章名>.md`，如 `姑苏九园-剧本-CH1沧浪亭.md`。

## 2. 分场卡：字段全表

每场一张卡。字段分七块，**全部填完才进入美术与程序生产**（对齐任务设计系统 §10、§13）。

### A. 身份块

| 字段 | 写法 | 例 |
|---|---|---|
| 场号 | `<章>-<两位序号>` | `CH1-03`，序章用 `PRO-03` |
| 题名 | 3–6 字，可用玩家不会看到的工作名 | `岔路相遇` |
| 层级 | 府学 Home / 《蘇城全圖》世界层 / 园林图 / 构件近景 | `园林图` |
| 时长预算 | 秒，或"30 秒–2 分钟" | `约 40 秒` |
| 任务类型 | 课业 / 请托 / 寻访 / 旧影 / 回访 / 自得 | `课业` |
| 任务 ID | kebab-case，稳定不变，与程序一致 | `canglang-three-windows` |
| 状态 | 草案 / 待测 / 定稿 / 已实现 | `定稿` |

### B. 进入条件块

| 字段 | 写法 | 说明 |
|---|---|---|
| 前置 flag | `storyFlags` 中的键 | `home-orientation-complete` |
| 前置园态 | `gardens.<id>` 至少为 | `gardens.canglang ≥ open` |
| 前置六艺 | `arts.<id> ≥ n` | `arts.shuMath ≥ 0` |
| 触发物 | 玩家走近/交互什么 | 走近共读桌；不主动弹出 |
| 可否跳过 | 是 / 否 | 所有非首次演出必须可跳 |
| 回看入口 | 可直接跳转的 URL 参数 | `home.html?scene=briefing` |

**规则**：触发条件必须写成"玩家做了什么"，不写"系统弹出了什么"。对齐连续序章定案 §5 的四阶段出现规则。

### C. 内容块（六节拍 × 演出）

按任务设计系统 §3 的六节拍逐拍填。**不是每一场都含六拍**——2–5 分钟的小任务含一次"循迹—行动—领悟"，10–15 分钟庭院段含三次小循环组一次完整回响。

每拍填三样：

| 项 | 内容 |
|---|---|
| 画面与镜头 | 看什么、镜头在哪、如何连接前后场 |
| 台词 | 见 §3 台词表规范 |
| 玩家选择 | 有则写选项与对应回应；无则写"无" |

### D. 机制块

| 字段 | 写法 |
|---|---|
| 主动词 | 本场唯一最重要的空间或观察动作（对齐六艺） |
| 判定 | 判定什么、怎么判（对齐 `ui/viewfinder.ts` 现有状态机：机位距离判定，不做图像识别） |
| 参数 | **引 `config.ts` 键名**，如 `TUNING.viewTriggerRadius`；新参数先登记再引用 |
| 三层提示 | 环境 / 学子自语 / 人物点醒，各一条（对齐 §9.2） |
| 失败与重来 | 无不可恢复失败；错误行动须返回有用环境信息 |

### E. 产出块

| 字段 | 对应程序 | 幂等要求 |
|---|---|---|
| 写入 flag | `storyFlags[]` | 只增不改 |
| 奖励 | `arts[]` 或 `gardens[]` 或 `knowledge[]` | **必须幂等，同一任务只结算一次** |
| knowledgeEntries | `knowledge[]` 的 key | 与任务结果绑定，不作前置考试条件 |
| worldChanges | 存档绑定的永久变化 | 不由页面临时显示 |
| replayPolicy | 可重看/重做/换时令，不重复给成长 | 对齐 §14 技术红线 |

奖励只能落在四类：六艺新动作 / 世界新连接 / 园谱新内容 / 人物新关系。**本阶段无金钱、无经验值、无道具稀有度、无每日任务。**

### F. 考据块

| 字段 | 写法 |
|---|---|
| 真实锚点 | 具体到建筑、构件、植物、碑刻、城市地点 |
| 证据等级 | A 实锤 / B 锚定 / C 候选 / 传说 / 虚构 |
| 界面标注 | 史实可核 / 合理演绎 / 民间传说（三者必选其一） |
| 未查证项 | 列出本场涉及但尚未核实的条目，**未查证项不得写进台词当事实** |

纪律（对齐考据三表使用规则）：标"未查证"的不得作为事实写入文案；标"线索/存疑"的只能作美术与关卡灵感方向。

### G. 生产块

| 字段 | 内容 |
|---|---|
| 美术需求 | 场景/tile/立绘/UI，注明复用还是新增 |
| 音频需求 | 环境声/交互声，是否由玩家手势触发 |
| 无障碍 | 声音字幕、静音可通关路径、prefers-reduced-motion |
| 验收点 | 玩家完成后能**用自己的话**说出什么（质性、不看数据） |
| 失败信号 | 什么现象说明这一场失败，命中后改什么 |

## 2.5 玩法卡：字段全表（戏中戏 A 轨 / B 轨）

**来源**：《姑苏九园-戏中戏·内置小游戏设计》**v1.0**（定案）。分场卡管**叙事场次**，玩法卡管**玩法本身**——一张卡 = 一款玩法，A 轨（茶馆玩意儿·消遣）与 B 轨（章内机制·课业）**共用本卡，靠"轨"一栏区分**。

七块与分场卡同构，但 **C／D／E 三块换过内容**（局面、评级、隔离）。**A 轨卡不填 C 之外的奖励栏，这是硬约束。**

### A. 身份块

| 字段 | 写法 | 例 |
|---|---|---|
| 编号 | A 轨 `M<n>`，B 轨 `B<n>` | `M1` |
| 名 | 3–6 字 | `灯谜条` |
| 轨 | `A 戏`（消遣，不发六艺） / `B 课`（章内机制，发六艺） | `A 戏` |
| 场所 | A 轨：城市场所名；B 轨：园 id + 章内位置 | `茶馆（第一批唯一场所）` |
| 主持人 | **用已有角色，不新增** | `说书先生` |
| 状态 | 草案 / 待测 / 定稿 / 已实现 | `草案` |

### B. 进入与退出块

| 字段 | 写法 | 说明 |
|---|---|---|
| 前置 | `storyFlags` / `gardens.<id>` 至少为 | A 轨一般无前置 |
| 进入方式 | **走近或与主持人对话** | **不许列在任何菜单里**（对手局尤禁） |
| 可退出 | **随时可退，退出不判负** | 红线 9 |
| 输的后果 | **无**——不扣任何资源，可立刻再来 | 红线（不得惩罚） |

### C. 局面块（玩法卡独有）

| 字段 | 写法 |
|---|---|
| 机制一句话 | 本款核心动作，一句话说完 |
| 局面 / 题序 | **固定**。**严禁做 AI 对弈**——残局也用固定局面 |
| 三层难度 | 初局 / 中局 / 难局，**只换局面参数，不换机制** |
| 参数 | 引 `config.ts` 键名，或标 `[待登记]`（同 §5） |
| 时长预算 | 平均一局秒数 |

### D. 评级块（玩法卡独有）

| 字段 | 写法 |
|---|---|
| 品第四档 | **能品 / 妙品 / 神品 / 逸品**（A 轨普通款**封顶神品**） |
| 逸品归属 | **只属对手局**——门槛、不放宽 |
| 记分 | 只记本机最高分；**不联网、无排行、无全球榜** |

### E. 产出块（隔离条款 —— 与分场卡最大的不同）

| 字段 | A 轨（戏） | B 轨（课） |
|---|---|---|
| 写入 flag | **无。不进 `StoryFlag` 主表** | 按该场写 |
| 存档命名空间 | **`minigames`**，键形如 `mg-teahouse-riddle::best` | 随主表 |
| 六艺 | **一律不发**（守 §C3.1） | 按 §C3.3 课业通道发 |
| 奖励 | **四类全不给**，只落**园谱「玩意儿记」一格**（场所／最高品第／最高分） | 园谱 / knowledge / 六艺 |
| 禁止 | **不给钱、不给经验、不给道具稀有度**（任务定案 §8） | 同左 |

### F. 考据块

| 字段 | 写法 |
|---|---|
| 玩法来源 | **必须回答"为什么只有这里有这款"**——由该场所真实特性导出（《游戏形态》§8.2） |
| 内容来源 | **自撰 / 化用某书**，**逐条登记**（外化于"未查证"的不得写成事实） |
| 证据等级 | A 实锤 / B 锚定 / C 候选 / 传说 / 虚构 |
| 界面标注 | 史实可核 / 合理演绎 / 民间传说 |
| 未查证项 | 逐条列出 |

### G. 生产块

| 字段 | 内容 |
|---|---|
| 界面态 | **离开行走的独立界面**（棋盘屏／谜题屏），**不新增行走世界动词** |
| 美术 / 音频 | 注明复用还是新增；**守《统一像素视觉系统》，禁止高饱和街机风** |
| 无障碍 | 声音字幕、色觉可辨、prefers-reduced-motion |
| 验收点 | **唯一判据：玩家输完，手会不会自己点"再来一局"** |
| 失败信号 | 什么现象说明这款失败（命中后改机制，而非加奖励） |

**A 轨自检（生产前必过）**：

```text
[ ] 删掉整款，主线照样能通（不拦路）
[ ] 没有发六艺、没有给钱 / 经验 / 道具
[ ] 没有弹"获得 / 升级 / +1"横幅
[ ] 分数没有上《蘇城全圖》界面
[ ] 主持人换了台词，但没透露任何主线答案
[ ] 局面是固定的，没有做 AI 对弈
[ ] 所有参数可追到 config.ts 键名或标 [PLACEHOLDER]
[ ] 玩法由该场所真实特性导出，换一个场所就不成立
```

## 2.6 「今按」层：后世之评（近现代学人文字的唯一合法容器）

**来源**：CH5 网师园考据（《姑苏九园-网师园考据报告》v1.0 §0-3、§1）。分场卡管**叙事场次**，玩法卡管**玩法本身**，**今按管"后世之评"**。

### 2.6.1 它是什么

**「今按」＝游戏正文里唯一允许出现"后世文字"的一层。**

本项目有一条考据铁律：**1840 年以后的学人（陈从周、刘敦桢、童寯等）的话，一个字都不能进 1890 年的台词、题跋、旁白**——主角活在 1890，他不可能听见后世人的话。

但 **"不能用"不等于"不该用"**。这些人的话恰恰是本作最重要的审美与空间依据。解法不是堵，是**给它们一个标明年代的容器**：

> **「今按」——仿古籍按语体例。以「今按」二字起首，明示此语出自后世，不属于任何角色。**

**它不在世界观之内**：主角不知道它存在，园中人听不见它。它是"这本书的读者"附的一笔。
（沿用 CH4-13 已定的"知识条——**只给玩家，不给主角**"惯例。）

### 2.6.2 两种型

| 型 | 内容 | 例 |
|---|---|---|
| **名物今按** | 只正名、只交代沿革，**不引文**。一到两行 | CH4-13「这地方后来叫什么」；CH5-11「后世叫网师园」 |
| **引文今按** | 引近现代学人原句，**必须标 人名 + 书名**（版本页码无则标【待核】）。一到三行 | CH5-09 引陈从周《园林清议》 |

**一章合计不超过 2 条，其中引文型不超过 1 条。** 克制是这一层的全部力量所在——多则变注释体，全书失味。

### 2.6.3 五条硬规格

1. **时序铁律 · 今按永远在玩家之后。** 玩家先做、先说、先写；今按后附。**不许出现在玩家做出动作之前**——否则就成了"先给答案"，直接违反《故事开篇与核心人物定案》§4「不让旁白替玩家宣布感悟」。
2. **今按不解题。** 它是**回声**不是**解答**：不解释本章谜题、不给未给过的答案、不评价玩家选择的对错。它只做一件事——**说"后来也有人这么看"**。
3. **必须标出处。** 引文型：人名 + 书名；版本页码查得到就标，查不到标 **【待核】**。**不得改造原句**——转述与原文分开，**转述不许加引号**。
4. **只给玩家。** 主角不知道，NPC 不回应，世界层（《蘇城全圖》）不显示。
5. **与玩家手迹分离呈现。** 今按**不是**角色的笔迹：须用**与手迹不同的字体/墨色**，并以「**今按**」二字起首。玩家一眼可辨"这不是他写的"。
   > ⭐ **已工程化（2026-09-30，白模 `gusu-whitebox/`）**——分离不再是"一句要求"，而是 **七个可检查的轴**（唯一真源 `config.ts → TYPE_LAYERS`，渲染原语 `src/render/annotation.ts`）：
   >
   > | 轴 | 玩家手迹 | 今按 |
   > |---|---|---|
   > | 字体 | **楷体**（写出来的） | **宋体**（印出来的） |
   > | 墨色 | 焦墨 `ink` #2b2824 | **重墨** `inkHeavy` #55524a（轻一档，不夺正文权威） |
   > | 字号 | 16 px | **12 px**（古籍按语是小字） |
   > | 起首 | 无 | **「今按」二字**（`inkMid`） |
   > | 界行 | 无 | **左侧细竖线**（`inkPale`——古籍版框界行的意译） |
   > | 纸底 | 正文纸 `paper` | **贴条纸** `wall`（更亮更冷——"从别处来的一张纸"） |
   > | 印 | **朱印** `zhu`（全作唯一重色） | **绝无印** |
   >
   > **时序轴由渲染器强制**：`annotationAlpha(actionAt, now)` 在 `TUNING.annotationDelayMs` 之内恒为 0——**这就是剧本里写的那个「稍顿」**（落笔 → 页成 → **稍顿** → 今按浮出）；之后按 `annotationFadeMs` 分 `annotationSteps` 级**阶梯**淡入（像素纪律，不用 CSS 缓动）。**结构上不可能"先给答案"。**
   > **零新增颜色**：今按只复用 inkHeavy／inkMid／inkPale／zhu／paper／wall 六个既有色。
   > **验收/调参**：`gusu-whitebox/annotation-lab.html`（三层对照 ＋ delay 滑杆 ＋ 全作 12 处实例逐条浏览 ＋ 本表自检）。
   > ⚠️ **本条债已在 CH5 起连欠五章、终章乙幕整幕依赖——现已落地。**

### 2.6.4 与既有铁律的关系（**不是例外，是出口**）

- 「近现代人禁入 1890」**依然成立**——今按不在此列，因为它**自己标着年代**（起首二字 + 出处），且**不在世界观之内**（规格 4、5 保证）。
- 判据一句话：
  > **能进台词的，只有 1890 年以前的人；能进「今按」的，才是我们这一代的人。**

### 2.6.5 材料源（**项目头号挂起项的正解**）

项目长期挂起三本书——《苏州古典园林》（刘敦桢）、《说园》《园林清议》（陈从周）、《江南园林志》（童寯）——一直卡在"原文未调阅"，并因此卡住窗二纹样、古树图鉴、《说园》台词母本等多项。

**「今按」就是它们进入游戏的唯一通道**：**逐章按需调阅，摘一句，标一处，成一按。不必等全书通读。**

> 这把"阻塞项"直接转成"设计资源"——原书调阅从"开工前置"降级为"每章的采集动作"。

### 2.6.7 终章尾幕：今按层的**终点**，不是**越界**〔v1.3 立〕

**问题**：§2.6.2 写着「**一章合计不超过 2 条，其中引文型不超过 1 条**」。而《剧本-终章回看苏州》的**乙幕·尾幕**（T-06〈对折〉／T-07〈一百三十六年〉／T-08〈请君入园〉）是**整幕皆今按**——它远远超过 2 条。**这算不算破坏规范？**

**判据＝不算。因为它与 §2.6.2 管的是两样东西。**

| | ① **嵌在叙事里的小字**（章末附按） | ② **整幕站在世界之外**（终章乙幕） |
|---|---|---|
| 位置 | 嵌在 1890 的世界里 | **整个不在 1890 里** |
| 是什么 | 主角活在 1890，**读者从外面附的一笔** | **"这本书"的最后一册附录本身** |
| 约束 | 必须克制，**故限 ≤2 条** | **它就是"今按"这个容器**——不限条数 |

> **判据一句话**：**≤2 条管的是"嵌在世界里的按语"；乙幕不是按语——乙幕是世界之外的那一册。**

**因此**：乙幕**不适用** §2.6.2 的条数上限，但**必须继续满足 §2.6.3 五条硬规格**（并有两条做到最大化）：

| 规格 | 乙幕如何满足 |
|---|---|
| **1 时序在玩家之后** | 乙幕在**甲幕玩家落款之后**才出现——它是"回声的尽头"，**绝不先给答案** |
| **2 不解题** | 乙幕**不解释任何本章谜题**，只呈现"后来也有人这么看" |
| **3 必标出处** | 世界遗产名录年份／UNESCO 评语／平江街区奖项／地铁站点**逐条标来源**（见《终章》§七） |
| **4 只给玩家**（**最大化**） | **乙幕里主角不在场、NPC 不出现、不入 knowledge、不给 flag、不进园谱、不上《蘇城全圖》** |
| **5 与手迹分离**（**最大化**） | 乙幕**整幕换了呈现介质**——不是"另一种字体"，而是"今天的画面"。**分离做到全作最大** |

**一条硬约束（防滥用）**：
> ⚠️ **本例外只适用于"全作最后一册"（终章尾幕）。不得前移，不得复制到任何园章的中间，不得作为"某章今按多一点"的借口。**

**为什么不做成"章末附 2 条"**：因为那会让终章的现代回声退化成一条脚注。本项目既已在 §2.6 给后世之评开了一个容器，**这个容器的最大形态就应当是终章的结尾**——**不是破例，是把 §2.6 用到底。**

## 3. 台词表规范

台词分三类，**同一场里分开列，不混排**（对齐连续序章定案 §6.2）。

| 类型 | 用途 | 例 |
|---|---|---|
| 人物台词 | 推进关系与眼前行动 | “先认得回来，再忙着出去。” |
| 观察文字 | 写材质、痕迹、空间，**不下结论** | “案角有一道被衣袖磨亮的弧。” |
| 系统文字 | **只确认动作结果** | “你把书箱放稳了。” |

排版：

```text
[场号.L序号] 说话人：台词
[场号.O序号] 观察：文字
[场号.S序号] 系统：文字
```

硬约束：

- 单个对话气泡 **8–28 个汉字**；
- 一轮普通交谈 **不超过 4 句**；
- 人物允许说半句、转身、继续做手上的事；
- **重要句子不同时承担知识解释与情绪表达两种任务**；
- 历史信息必须进入某个人正在做、记得或争论的事，不让 NPC 当百科全书。

禁止写法（对齐 §6.3）：

- “苏州是一座有着两千五百年历史的文化名城”；
- “昆曲是中国最古老的戏曲之一”；
- “这里就是苏州府学，始建于……”；
- “已解锁 Home、地图系统、人物图鉴”；
- 人物第一次见面就自述姓名、职业、性格、擅长六艺和长线矛盾；
- 为显古雅让所有人持续使用艰深文言。

## 5. 参数与 [PLACEHOLDER] 规范

`config.ts` 是所有数值的唯一出口。剧本中写参数的三种合法写法：

| 情况 | 写法 | 例 |
|---|---|---|
| 参数已存在 | 写键名 + 当前值 | `TUNING.viewTriggerRadius = 22` |
| 参数需新增 | 写键名 + `[待登记]`，同时在剧本末尾汇总 | `TUNING.win2LaneWidth [待登记]` |
| 尚未测定 | 写 `[PLACEHOLDER]` + 待测项 | `窗三停步判定帧 [PLACEHOLDER 待纸面测试]` |

**禁止**：在剧本里直接写"判定半径 22 像素"这种脱离键名的裸数字。数值只允许出现在两处——`config.ts`，或剧本的参数引用行。

每份剧本文件末尾附一张**参数汇总表**：

```text
| 键名 | 当前值 | 状态 | 来源 |
|---|---|---|---|
| TUNING.moveSpeed | 64 | [PLACEHOLDER] | config.ts |
| TUNING.win2LaneWidth | — | [待登记] | 本剧本 CH1-05 |
```

- 界面标注：合理演绎
- 未查证项：城南具体街巷细部、昆曲曲牌与唱腔（**须音乐顾问确认后锁定，未定前用环境声与无歌词哼唱占位**）、清末该段街道的招幌与铺面形制

- 失败信号：若玩家认为刚看完一段“游戏设定说明”，本场失败，重写镜头与台词密度
