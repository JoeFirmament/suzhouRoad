# 小飞虹 Web Demo · 垂直切片标准

> v1.0（2026-09-28）· 适用于《姑苏九园》Web 像素游戏。小飞虹是视觉与交互基准，不是九园通用地图模板。

## 1. 定位裁决

小飞虹 Demo 同时承担两种职责：

1. **视觉基准**：回答“园林在浏览器里应当精细到什么程度、什么构件必须一眼可认、人物如何被屋顶/栏杆/植被正确遮挡”。
2. **交互基准**：回答“键鼠与触屏是否共享逻辑、一个 2–3 分钟局部场景是否有明确开始/进行/完成状态”。

它不规定九园的地图比例、任务内容和机制。沧浪亭仍以“复廊三窗·看—对—合”为核心；拙政园小飞虹的“沿桥漫游”不能被复制成沧浪亭玩法。

## 2. 三件基准材料

| 层级 | 当前材料 | 用法 |
|---|---|---|
| 实景证据 | `../xiaofeihong-reference.jpg` | 校验桥折线、朱栏、黛瓦、水岸关系；事实层优先级最高 |
| 视觉母版 | `../artwork/zhuozhengyuan-xiaofeihong-2.5d-pixel.png` | 定构图密度、色彩倾向、像素颗粒与前后景；只作概念母版 |
| 可玩样板 | `../Owner_ClassicGarden/game/xiaofeihong/` | 验证人物尺度、路线、遮挡、键鼠/触屏、反馈闭环 |

纪律不变：AI 生成图不能直接拆成九园正式 tile。正式资产仍须按词表和实景证据，在锁定色板内人工重绘；图片底图玩法只属于“参考 Demo”轨道。

## 3. 双轨工作法

### A. 参考 Demo 轨

- 允许以视觉母版整图为场景底图，快速验证人物比例、路线、遮挡和交互。
- 用途是设计评审、传播和确定观感，不作为正式地图数据源。
- 当前小飞虹可玩样板就是本轨基线。

### B. 正式生产轨

- 可信图纸/实景证据 → 构件词表 → 语义 tile 地图 → 2.5D 分层渲染 → 机制判定。
- 碰撞和谜题使用地图数据，不从图片像素反推。
- 当前 `gusu-whitebox` 的沧浪亭整园、复廊试铺属于本轨。

两轨必须在“视觉验收”会合：正式生产轨应达到参考 Demo 的识别度、层次和操作完整度，但不复制其图片或路线。

## 3.1 双镜头层级（2026-09-28 增补）

园林大地图与 Demo 级画面解决的是两件不同的事，禁止再用一套镜头同时承担：

- **整园导航层**：保持可信平面、自由游走、POI 可达和方位认知；允许使用较远的 tile 视角，不作为美术终局截图。
- **英雄场景层**：进入核心构件后切到近景构图；单个建筑/复廊占画面 35–45%，有明确前景、中景、后景和可遮挡区域，承载该园招牌机制。

沧浪亭当前英雄场景为 `gusu-whitebox/corridor.html`：葑溪前景—复廊主景—山林后景，承载三窗“看—对—合”；`garden.html` 改为整园导航层，不再与小飞虹近景 Demo 直接比较。

## 4. 场景分层标准

每个正式场景至少有以下五层，禁止把人物永远画在最上层：

| 顺序 | 层 | 内容 | 验收 |
|---|---|---|---|
| 1 | ground | 草地、路、水、桥面 | 相机移动时稳定，无接缝 |
| 2 | rear objects | 玩家身后的墙、石、树、建筑 | 不错误遮挡玩家 |
| 3 | actor/effects | 玩家、任务反馈、局部动效 | 脚底锚点与碰撞位置一致 |
| 4 | foreground/overhang | 屋檐、近岸植被、前栏 | 玩家走到其后方时自然被遮挡 |
| 5 | screen UI | 取景框、题跋、朱印、操作反馈 | 不烘焙进像素资产 |

`garden25d.ts` 的逐行 strips 是正式实现；小飞虹 Demo 的裁剪回绘只作为快速原型方法。

## 5. 视觉验收清单

每个园的垂直切片至少包含“一条可走路径 + 一个核心构件 + 一个机制瞬间”，并同时满足：

- 一眼可认：不看标题也能从构件判断园林局部；小飞虹至少保留折线廊桥、朱栏、黛瓦、水影、湖石。
- 限色一致：正式资产只使用 `assets/palette/palette.json` 登记色；单园强调色不超过 8 色。
- 像素一致：逻辑 tile 为 16 px；只用整数倍缩放；Canvas 关闭平滑。
- 尺度一致：角色脚底、栏杆高度、檐口高度在连续场景中不跳变。
- 遮挡正确：至少验收“檐下、栏后、树前/后”三个位置。
- 文图分离：匾额、诗句、任务文字由 UI/字体渲染，不写死在底图。
- 动静有别：水面/树影可以轻动；建筑轮廓不能因动效漂移；尊重 `prefers-reduced-motion`。

## 6. 交互验收清单

- 键盘：WASD 与方向键移动，E/空格/Enter 交互，Esc 退出取景。
- 触屏：方向键支持按住连续移动；“取景/退出”按钮可独立操作；按钮不触发页面滚动。
- 同构原则：键盘与触屏只提供轴值/动作，不各自修改玩家坐标，必须共用碰撞、速度与判定逻辑。
- 反馈闭环：进入场景后 30 秒内知道该做什么；2–3 分钟内能完成一个局部目标；完成态清楚但不弹教程清单。
- 可恢复：切后台、失焦或触控取消时立即清空移动输入，人物不能持续漂移。
- 可访问：Canvas 有场景说明；按钮有可读标签；重要状态不能只靠颜色表达。

## 7. Web 性能与发布门槛

- 首屏资源目标 ≤ 10 MB；单张场景图建议 ≤ 3 MB；生产场景优先 tile/atlas。
- 目标 60 fps；中端手机持续低于 45 fps 时，先减少逐帧重绘和透明大图，再考虑降画质。
- 同一 URL 支持桌面和手机；需在 iOS Safari/WKWebView 与微信内置浏览器各做一轮实机检查。
- 不依赖 CDN 才能启动；音频必须在用户手势后解锁。
- 构建后执行类型检查、地图可达性检查、三处遮挡截图和一次完整交互回归。

## 9. 下一推进顺序

1. **先验收复廊切片**：用小飞虹并排只看识别度、层次、人物尺度和触屏手感，不比较地图内容。
2. **跑 5 人轻量测试**：记录窗三停步次数、是否主动使用取景、手机误触率。
3. **回填 `config.ts`**：只调整移动速度、触发半径、0.3 秒静默拍等参数。
4. **冻结沧浪亭正式样板**：视觉、交互、机制三项同时过线后，才向网师园复制工程骨架。
5. **逐园换“园性”**：复制技术契约，不复制场景玩法；每园仍以自己的机制构件过验收。

## 10. 完成定义（Definition of Done）

一个园的 Web 垂直切片只有在以下四件事同时成立时才算完成：

1. 可信证据能说明“为什么这样画”；
2. 视觉能让玩家认出“这是哪一处”；
3. 前后景、碰撞、键鼠与触屏都通过回归；
4. 核心机制从开始到完成能在一次短局中闭环。

只完成概念图、只完成可走地图或只完成剧情文档，都不算垂直切片完成。
